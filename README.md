# VideoSeal 本地小 Demo

## 网页实验台（新增）

双击 `run_web.cmd`，打开 **http://127.0.0.1:8765**。后端使用 FastAPI，网页使用原生 HTML/CSS/JavaScript，无需前端构建。

首次安装：

```powershell
powershell -ExecutionPolicy Bypass -File .\setup_web.ps1
# 可选 VAE 后端：安装依赖并下载约 320 MB 的模型
powershell -ExecutionPolicy Bypass -File .\setup_web.ps1 -WithVae
# NVIDIA CUDA 加速（安装官方 CUDA 12.6 版 PyTorch；无需单独安装 CUDA Toolkit）
powershell -ExecutionPolicy Bypass -File .\setup_web.ps1 -WithVae -WithCuda
```

当前电脑已安装网页依赖并准备好 VAE。处理时读取本地模型，不上传视频、不调用云端推理。

### 加速与实际设备

- 默认自动选择 CUDA，VAE、频谱优化、VideoSeal 引导及已知消息验证均在所选计算设备执行。去噪优先使用 OpenCL GPU；DCT / 小波、参考残差、几何和光流处理仍在 CPU 执行。
- 默认优先使用实测可用的 `h264_nvenc` 编码；小尺寸或 NVENC 编码失败时回退 `libx264`，在日志和报告中记录实际编码器。前后对照保持相同编码器。质量数值在 CPU 对应 CRF，在 NVENC 对应 CQ，二者不保证相同码率和画质。
- 模型按设备缓存复用。GTX 1660 使用 FP32，VAE 按画面大小和可用显存选择整帧、512 px 或 256 px 分块；显存不足时缩小分块并重试当前帧，后续帧沿用成功方案。CPU 保持 256 px 分块。画面尺寸、精度和迭代次数保持用户设置。
- 网页“算法与验证设置”可以分别指定模型计算设备（自动 / CPU / CUDA）、编码设备（自动 / CPU）、VAE 方式（自动 / 原版 256 px）和去噪设备（自动 / CPU / 仅 GPU）。强制 CUDA 或 GPU 去噪不可用时明确报错。
- GPU 去噪使用现有 OpenCV 的 OpenCL `UMat` 路径，不要求安装 CUDA 版 OpenCV；启动时检查实际 GPU 和去噪调用，任务线程再次启用 OpenCL。自动模式遇到 GPU 错误时切回 CPU，日志和报告记录实际设备。OpenCL 去噪与 CPU、不同 VAE 分块的输出会有少量像素差异，需要复现旧结果时选择原版 VAE 和 CPU 去噪。
- 进度显示当前帧和当前方法；JSON 报告包含模型加载、各方法、编码、验证耗时及实际设备。显卡不可用时自动选择 CPU，但 CPU 上的高分辨率 VAE 仍可能较慢。
- 两份参考视频内容完全相同时会在提交阶段拒绝任务，避免重复解码、加载模型和无效处理。

本机 GTX 1660 6 GB 的同帧实测（720×1280、强度 5、6 次迭代、FP32）：VAE 从 CPU 约 79.3 秒/帧降至 CUDA 首帧 5.3 秒、后续 5.0 秒/帧；VideoSeal 引导从 CPU 首帧 3.36 秒降至 CUDA 热身后 0.19 秒/帧。CUDA 首次引导调用另有约 6.7 秒的初始化开销，因此这些倍数不是整段视频或八种方法总耗时的倍数。原始测量见 `outputs/benchmark-before-cpu.json` 与 `outputs/benchmark-after-cuda.json`；可用 `research/benchmark_speed.py --label <名称> --device cpu|cuda` 复测。

2026-10-30 分块与去噪优化实测见 [测量说明](research/gpu_processing_2026-10-30.md)。同一原片的单帧、强度 3、一次预热后测量两次：1080×1920 的 VAE 从 11.48 降至 10.43 秒/帧，去噪从 1.47 降至 0.59 秒/帧。这是模块耗时，完整任务仍包含解码、其他算法、编码与验证。已有服务需要关闭启动窗口并重新运行 `run_web.cmd` 后加载新后端；旧后端运行时，新控件禁用并提示重启。

2026-11-04 新增可选“快速 · 轻量模型（重建效果不同）”：在“算法与验证设置 → VAE 运算方式”中选择。它使用本地 `madebyollin/taesd` 重建，保持所选尺寸和 FP32；原模型仍是默认选项。GTX 1660 上同组 1080×1920 画面、强度 3，原模型预热后约 10.30 秒/帧，快速模式约 0.95 秒/帧，VAE 模块约快 11 倍；这不是七个模块的整体提速倍数。轻量模型与原模型的重建结果不同，细节和颜色可能变化，也没有未知平台水印清除结论。原始记录和画面对比见 [测量说明](research/vae_speed_2026-11-04.md)。

当前电脑已准备轻量模型。其他电脑安装现有 VAE 依赖后，可运行 `.\.venv\Scripts\python.exe prepare_vae.py --tiny` 下载约 10 MB 的可选模型。任务执行只读取本地权重；缺少所选模型时明确报错，不会自动换用另一种模型。

2026-11-04 另优化 DCT、几何映射和时域计算中的内存复用与缓存，不改变算法组合、参数或帧覆盖范围。同组全高清样本中三项累计从约 1.01 降到 0.68 秒/帧，CPU 模块输出逐像素一致；这不是整套七模块的提速倍数。详见 [CPU 优化测量](research/cpu_processing_2026-11-04.md)。运行中的任务继续使用原先加载的代码，下次重启服务后生效。

网页支持单个或批量选择 / 拖入视频、组合处理顺序、参数调整、取消任务、历史记录、前后视频播放及结果下载。默认勾选 DCT / 小波、频谱约束优化、去噪与重建、VAE、几何同步扰动、VideoSeal 引导、时域运动补偿七项；参考载波抵消需手动选择并提供对齐参考片。恢复默认会同时恢复这七项选择。

一次可选择最多 50 个视频，单个文件不超过 512 MB，可分次添加或移除。点击开始后，对本批所有文件使用提交时的同一组参数，逐个上传并进入串行队列；批量面板显示每个视频的排队 / 处理进度、错误、查看与下载入口，也可取消本批未完成任务。单个上传或处理失败不阻断后续文件，已提交文件从待上传列表移除，失败文件保留以便重试；重复提交相同上传请求不会重复创建任务。结果下载使用原视频名加“_处理后”，避免混淆。

已提交任务及批次标识写入本地历史，当前批量面板在同一浏览器刷新后可恢复。上传结束前需保持页面打开；未提交文件的本地读取权限不能跨刷新保留，需要重新选择。历史任务不会因新建批次被删除。提供以下八类独立实验实现：

| 方法 | 当前实现与条件 |
|---|---|
| DCT / 小波处理 | 分块 DCT 重新量化，或 Haar 小波软阈值 |
| 参考载波抵消 | 需要内容、时间、尺寸已对齐的原片和水印片；从最多 32 帧估计共同残差，保留选定的 FFT 频带后抵消。压缩差异也可能进入残差 |
| 频谱约束优化 | 256 px 优化副本上的频谱差异目标、均方误差约束及像素变化上限；再映射回处理尺寸。不是 UnMarker 完整复现 |
| 去噪与重建 | OpenCV 非局部均值去噪，优先 OpenCL GPU，可选 CPU 兼容路径 |
| VAE 重建 | 本地 `stabilityai/sd-vae-ft-mse` 编解码，强度控制原图与重建的混合比例；模型位于 `checkpoints/sd-vae-ft-mse` |
| 几何同步扰动 | 固定的平滑局部位移场；跨帧不随机更换位移场 |
| VideoSeal 引导优化 | 通过配套 TorchScript 提取器梯度降低消息 logits 幅度，仅用于已知 VideoSeal 的实验 |
| 时域运动补偿 | 光流对齐前一帧后混合，检测到较大场景变化时跳过；不保证能削弱帧内水印 |

处理副本由用户明确选择：前 2 / 10 / 30 / 60 / 300 秒，尺寸上限 256–1920 px，4–30 FPS。“处理哪些帧”默认逐帧执行，也可选择“随机抽帧”，填写随机处理帧数（默认 10）和种子（默认 42）。从经过尺寸、帧率转换的所选片段中无重复抽取 N 帧，仅这些帧执行所选方法；N 超过总帧数时全部处理。其余帧跳过算法，输出仍覆盖所选时长，仍会缩放、重采样和有损编码。随机模式中的时域处理参考紧邻上一帧，不跨越未选中的长间隔。

1080×1920 竖屏原片可选择“1920 px · 支持 1080 × 1920”和“30 FPS”，以保留原分辨率与帧率；1920×1080 横屏同样支持。尺寸上限只缩小、不放大原片。该选择适用于单个、批量任务及完整时长导出；输出仍会执行所选算法和有损编码，不保证原码率或无损画质。1920 选项需要新版后端支持，旧服务运行时会禁用该选项并提示重启。

随机抽帧能减少算法计算量，仍需解码和编码完整片段；画面切换可能闪烁，少数帧发生变化不代表整段水印失效。逐帧和随机模式均最多输出 9000 帧（30 FPS 下最多 300 秒）；单文件最多 512 MB。相同总帧数、N 和种子可复现抽帧位置，报告 `sampling` 记录实际处理帧数、比例、种子和从 1 开始的帧号。对照图片取第一张被选中的帧；视频画质与消息指标仍抽样前 10 秒，可能未覆盖随机处理帧。

“下载视频包含”可选“仅处理片段”（默认）或“处理片段 + 剩余原视频（完整时长）”。例如原视频 150 秒、选择处理前 2 秒：前者导出约 2 秒，后者导出约 150 秒，后 148 秒不执行算法。完整模式将处理后的前段与原视频后段统一到所选处理尺寸、帧率后编码，并从原视频连续保留整段音频；后段仍会有缩放、重采样和有损编码，不是无损复制。下载文件为本次选择的导出范围，左侧对照预览仍只含处理片段；报告 `export` 记录输出实际时长、处理时长、后段时长和规格。算法抽帧上限只约束前段，后段不抽取 PNG 或执行模型。

2026-11-04 修正长视频提交：逐帧与随机模式统一为 9000 帧上限。旧后端尚在运行时，新页面会将逐帧请求转换为“随机模式选择全部 9000 个候选帧”，实际仍对所选片段每一帧执行算法，尺寸、帧率及算法组合保持用户设置；无需中断正在处理的任务。刷新页面可加载兼容提交逻辑；原先失败的视频需要重新选择并提交。

当前串行处理，最多允许 50 个未结束任务。输出是 SDR / 8 位 H.264 视频，音频转为 AAC；仅片段模式保留对应片段音频，完整模式保留整段音频。变帧率输入会重采样为所选恒定帧率。需要保留完整原始规格时，请勿将本实验输出作为母版。

每个任务保存在 `outputs/web/<任务ID>/`，包含原始上传文件、抽取帧、同设置的 `before.mp4`、`result.mp4`、抽样帧与放大差异、`job.json`、`report.json`。服务重启后保留历史，运行中和排队中的任务标记为“中断”，不会自动重新执行。取消操作保留已有文件，不提供自动清理或物理删除功能。

指标从实际保存的前后 MP4 重新解码：前 10 秒以 2 FPS 抽样、最多 16 帧、尺寸上限 256 px，计算 PSNR / SSIM。它们描述抽样画质，不描述水印是否存在。只有验证样本或明确填写了 256 位参考消息时，才比较已知 VideoSeal 消息恢复率；同时报告考虑整串比特反转后的匹配率，防止将比特翻转误当作清除。未知平台视频始终显示“未验证”。

这是使用 Meta 官方 VideoSeal v1.0 TorchScript 模型的最小验证程序。

## 使用

当前电脑已准备独立的 `.venv` 环境与官方模型。双击 `run_demo.cmd`，点击“运行一次 Demo”。
也可以在 PowerShell 运行：

```powershell
Set-Location D:\workspace\videoseal-demo
.\.venv\Scripts\python.exe demo.py --self-test
```

默认使用 Meta 官方示例视频的前 2 秒。也可以在界面选择自己的视频，或使用：

```powershell
.\.venv\Scripts\python.exe demo.py --self-test --input "D:\视频\你的文件.mp4"
```

选视频时只处理前 2 秒、256×256、4 FPS 的演示副本，**不会修改输入文件**。
这里的小尺寸和低帧率是控制 demo 开销，不代表原视频会被修改。

## 流程与结果

1. 准备未新增水印的对照样本。
2. 嵌入一段已知的 256 位随机测试消息。
3. 保存为 H.264 MP4，再重新解码读取。
4. 使用模型的 extractor/detector 恢复消息，并与本次参考消息对比。

为便于小样本验证，8 帧逐帧嵌入、采用 H.264 CRF 12 轻压缩；水印强度保持官方模型默认值。
此演示不替代对强压缩、裁剪或复杂平台转码的鲁棒性评估。

每次运行在 `outputs/时间戳/` 新建目录，包含：

- `report.html`：本地可视化报告，包含匹配率、测试帧和两个测试视频。
- `report.json`：实际运行设备、用时、匹配率、参考消息和恢复消息。
- `clean_sample.mp4`、`watermarked_sample.mp4`：对照样本与带水印样本。
- `difference_x10.png`：把帧差异放大 10 倍供观察，不是实际水印外观。
- `message.json`：本次嵌入的已知消息。

“匹配率”是已知消息的位匹配率，**不是未知视频含有水印的概率**。
90% 只是此 demo 的自检阈值，不是经过通用场景校准的检测阈值。
未知视频即使输出了一串比特，也不能仅凭该结果判断有水印。

## 环境

- Windows，Python 3.12。
- 原始桌面 Demo 固定使用 CPU，最多 4 个线程；网页实验台支持 CUDA / NVENC，实际设备以界面和报告为准。
- CPU 模式无需 CUDA；GPU 模式通过官方 PyTorch CUDA 轮子提供运行库。不依赖完整 VideoSeal 训练项目或 torchvision。
- 系统 PATH 中需要有 FFmpeg。
- 官方模型约 218 MiB，保存于 `checkpoints/y_256b_img.jit`。
- 初次依赖和模型下载后，演示过程可离线运行，输入视频不会上传。

换电脑时，在该目录执行 `powershell -ExecutionPolicy Bypass -File .\setup.ps1` 安装。
环境安装在此目录内，不修改全局 Python 包。
